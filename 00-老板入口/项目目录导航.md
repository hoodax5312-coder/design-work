# 项目目录导航

这张表只解释“每个目录是干什么的”，不要求你理解代码。以后即使没有 Codex 在旁边，也先看这张表。

## 先记住一句话

你只需要日常看：`00-老板入口/`、`01-项目管理/`，以及我明确发给你的某份产品/设计资料。

其他目录大多是程序源码、运行配置或自动生成文件，不需要你逐个理解。

> 说明：为了不影响网站启动，程序必须使用的英文名称仍保留在电脑里，但已按“电脑专用内容”处理。看到它们时不要删除或移动；老板日常只看下面四个中文区域。

| 目录/文件 | 老板视角的解释 | 是否建议直接改动 |
| --- | --- | --- |
| `00-老板入口/` | 项目驾驶舱、中文说明、当前进展 | 可以阅读，修改前先沟通 |
| `01-项目管理/` | 计划、任务、决策、版本、风险、复盘 | 可以阅读；归档资料先确认 |
| `02-产品与设计/` | 产品规格、实施计划、设计探索和 UI 规范 | 先阅读，修改需明确任务 |
| `04-质量与验收/` | 截图审计、视觉问题和回归证据 | 只读为主 |
| `03-程序区/前端代码/` | 前端界面代码 | 不建议直接修改 |
| `03-程序区/后端服务/` | 本地服务、数据库、导入、预览、任务 | 不建议直接修改 |
| `03-程序区/启动构建/` | 启动、构建和环境检查工具 | 不建议直接修改 |

| `node_modules/` | 程序依赖包，安装后自动生成 | 不要手工修改或提交 |

## 三类目录怎么判断

### A. 程序运行必需

这些目录或文件是开发人员运行、构建和测试程序用的：

`03-程序区/`、`package.json`、`package-lock.json`、`vite.config.ts`、`tsconfig*.json`、`tailwind.config.js`。

它们不能随便删除或改名。你不需要直接管理它们；需要改功能时，由任务记录说明改了什么。

### B. 项目资料

这些内容帮助人理解项目：

`01-项目管理/`、`02-产品与设计/`、`04-质量与验收/`、`00-老板入口/`。

它们可以阅读，但历史资料、截图和文档是否复制到项目管理库，仍要先经过你的确认。

### C. 自动生成或工具数据

这些不是项目知识库：

`.mboard/`、`.gstack/`、`.vercel/`、`node_modules/`、`dist/`、`output/`。

它们可能会被程序、部署平台或开发工具自动重新生成。不要把它们当作版本事实，也不要手工清理。

## “能不能删？”快速规则

| 看到什么 | 老板动作 |
| --- | --- |
| 不认识的目录 | 先不要删除，发给 Codex 判断 |
| `03-程序区/` | 不要移动或改名 |
| `.mboard/`、`.vercel/` | 不要手工修改，可能影响本地运行或部署 |
| `node_modules/`、`dist/` | 属于自动生成内容，不需要你管理 |
| `02-产品与设计/`、`04-质量与验收/`、设计稿 | 可以阅读；归档前先询问你 |
| `01-项目管理/`、`00-老板入口/` | 这是你日常管理项目的地方 |

## 功能工作流

1. 老板或用户提出需求。
2. 在 `01-项目管理/06-任务与迭代/` 记录任务。
3. 在 `01-项目管理/07-决策与风险/` 记录需要确认的选择。
4. 在 `02-产品与设计/` 或 `04-质量与验收/` 查看产品和设计依据。
5. 工程人员修改 `03-程序区/`。
6. 通过测试和验收确认结果。
7. 在 `01-项目管理/05-工程与交付/` 记录版本和发布。
8. 在 `01-项目管理/09-复盘与交接/` 记录经验和下一步。
