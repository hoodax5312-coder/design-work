# 多图生成结果容器设计

## 背景

图片生成一次可返回 1 张、2 张、3 张、4 张或自定义数量的结果。当前 `GenerationRecord.outputs` 已能保存同批多张图片，但结果列表只渲染第一张，顶部下载与存入资产操作也只作用于第一张。需要让同批图片在同一个结果容器中展示，并保持已经确认的原比例适配规则。

## 目标

- 同一次生成的全部图片始终归属于一个结果记录和一个结果容器。
- 1 张、2–4 张、5 张以上分别使用明确且稳定的布局。
- 所有图片完整显示，不裁切、不拉伸。
- 图片级操作与批次级操作语义清楚。
- 键盘、鼠标和触屏均可完成查看与操作。

## 不在范围内

- 不改变图片生成 API、模型参数或并发请求策略。
- 不改变视频结果的展示方式。
- 不引入批量下载或批量存入资产。
- 不重构图片生成页面以外的模块。

## 已评估方案

### 等权自适应四等分（采用）

1 张保持大图；2–4 张固定为 2×2 等份布局，缺少的槽位纯留白；5 张以上折叠为叠放图片封面。优点是同批图片权重一致、位置稳定，且 4 张时利用率最高。

### 平衡拼贴（未采用）

3 张和 5 张突出首图，其余图片缩小排列。空间利用率较高，但会给同批结果制造不必要的主次关系。

### 主图加缩略图栏（未采用）

始终展示一张主图，其余结果作为切换入口。单图查看效率高，但无法同时比较所有结果，也与“同一容器直接展示多张”的目标不符。

## 展示规则

### 1 张

直接展示原图片，不进入四等分布局。

- 横图或方图：占满可用宽度，容器高度跟随图片真实宽高比。
- 竖图：展示区高度最高等于可用宽度，即最高为 1:1；图片按展示区高度等比缩放并水平居中。
- 最大展示高度沿用现有 680px 上限。
- 全程使用 `object-contain` 语义，不裁切图片。

### 2–4 张

使用固定的 2×2 四槽布局，顺序为左上、右上、左下、右下。

- 每个槽位宽度相等。
- 同一批生成图尺寸相同，因此四个槽位使用由首张成功加载图片确定的统一展示比例。
- 横图或方图：槽位比例等于图片真实宽高比，图片占满槽位宽度。
- 竖图：槽位展示比例封顶为 1:1，图片按槽位高度缩放并水平居中。
- 2 张占据第一行，第二行保留两个空槽；3 张额外占据左下槽；4 张填满。
- 空槽仅维持网格空间，使用 `visibility: hidden`，不绘制背景、边框、图标或提示文字。
- 槽位间距使用 8px，结果容器继续使用现有 16px 左右边距与 8px 圆角语言。

### 5 张以上

结果容器显示一个“叠放图片”封面，不继续压缩单张图片。

- 封面使用该批首张图片作为最上层缩略图，后方用两层轻微错位的同比例卡片表达集合。
- 封面遵守与单图一致的横图/竖图比例上限，不强制为 1:1。
- 右下角显示总数量，例如“5 张”。
- 点击封面打开批次图片弹窗。

## 操作与交互

### 批次级操作

结果标题栏保留：

- 编辑提示词：将该批次提示词带回输入区。
- 再次生成：使用该批次提示词重新发起一次生成。

这两个操作属于整批结果，不重复出现在每张图片上。

### 图片级操作

每张可见图片在鼠标悬停或键盘聚焦时显示：

- 下载
- 存入资产

操作层位于图片右上角，使用半透明深色表面与现有 Lucide 图标。按钮提供 `aria-label` 和 `title`，点击热区不小于 32px。触屏设备在大图预览中持续显示这些操作。

### 大图预览

- 点击任意图片打开大图预览。
- 预览保持图片完整显示，背景使用中性深色。
- 支持左右按钮和键盘方向键切换同批图片。
- 显示当前位置，例如“2 / 4”。
- `Esc` 关闭，关闭后焦点返回触发图片。
- 下载与存入资产操作在预览中持续可见。

### 5 张以上弹窗

- 点击叠放封面打开居中弹窗。
- 弹窗以两列自适应网格展示本批全部图片；窄屏降为一列。
- 网格中的图片继续遵守原比例适配和不裁切规则。
- 图片悬停或聚焦时显示下载、存入资产。
- 点击图片后，弹窗切换为大图预览状态；返回可回到全部图片网格，避免嵌套两个模态框。

## 组件边界

在 `ImageGeneration.tsx` 的现有模块范围内拆分以下职责：

- `GeneratedImagePreview`：负责单张图片加载、真实比例检测和不裁切展示。
- `GenerationImageGrid`：负责 2–4 张的固定四槽布局和空槽保留。
- `GenerationStackCover`：负责 5 张以上的叠放封面与数量标识。
- `GenerationBatchDialog`：负责全部图片网格、大图预览、左右切换和图片级操作。
- `GenerationResultMedia`：根据 `outputs.length` 在上述三种展示模式之间分派。

组件只接收批次数据和回调，不直接读取生成表单状态。下载、存入资产、提示词回填与再次生成仍由页面组件提供。

## 数据流与持久化

### 内存记录

沿用 `GenerationRecord.outputs: string[]` 作为同批图片的有序集合。视图始终根据 `outputs.length` 决定展示模式：

- `1`：单图
- `2–4`：四槽网格
- `>=5`：叠放封面

弹窗状态包含当前批次 ID、视图模式（网格或大图）和当前图片索引。

### 历史恢复

当前每张生成图片会单独写入 `contentFeed`，页面恢复时会被重建为多条单图记录。为保持批次，需要在新生成内容的 metadata 中增加：

- `generationBatchId`：同一次生成共享的稳定 ID。
- `generationIndex`：图片在批次中的顺序，从 0 开始。
- `generationCount`：该批次总数。

`feedHistory()` 按 `generationBatchId` 分组，并按 `generationIndex` 排序后恢复 `outputs`。没有 `generationBatchId` 的历史内容按单图记录处理，保证兼容旧数据。

右侧快速切换栏仍按批次显示一项：使用首张图片作为缩略图，多图时叠加数量标识。

## 加载与失败处理

- 图片尺寸未知时保留现有中性加载区，首张加载后再锁定本批槽位比例，避免四格抖动。
- 单张图片加载失败时保留该槽位尺寸，显示“图片加载失败”和重试入口，不影响同批其他图片。
- 下载或存入资产失败时沿用页面现有错误反馈，不关闭弹窗或大图预览。
- 图片生成请求仍保持当前整批成功或失败行为，本次设计不改变请求层逻辑。

## 可访问性

- 所有图片入口使用可聚焦按钮语义，支持 `Enter` 和 `Space` 打开预览。
- 图片级操作在 `hover` 与 `focus-within` 下等价显现。
- 弹窗打开后焦点进入弹窗并被约束在内部；关闭后返回触发元素。
- 左右切换按钮具有明确可访问名称，并支持键盘方向键。
- 数量、当前位置和错误状态使用可读文本，不仅依赖视觉图形表达。
- 尊重 reduced motion；叠放封面与弹窗只使用轻量淡入，不使用强位移动画。

## 验收标准

- 1 张图片继续按现有原比例规则展示。
- 2、3、4 张分别稳定占据固定四槽中的 2、3、4 个位置。
- 2、3 张的空槽纯留白，不出现可见占位元素。
- 横图占满槽位宽度并保持原比例；竖图展示高度不超过 1:1，按高度等比缩放并居中。
- 所有展示模式均不裁切图片。
- 5 张以上显示叠放图片封面与准确数量，点击后可查看全部图片。
- 每张图片的悬停和聚焦态均提供下载、存入资产。
- 点击单图可进入大图预览，并可通过按钮和键盘在同批图片间切换。
- 页面刷新后，新生成的多图批次仍恢复为同一条结果记录。
- 旧历史数据继续以单图记录正常显示。

## 验证计划

- 对 1、2、3、4、5 和自定义大于 5 的数量逐一进行浏览器验证。
- 分别验证横图、方图、竖图，检查自然比例、渲染比例和容器高度。
- 验证悬停、Tab 聚焦、Enter/Space、左右方向键和 Esc。
- 验证下载、存入资产、编辑提示词和再次生成的作用范围。
- 验证刷新前后批次分组、顺序和数量一致。
- 验证单张加载失败不会破坏网格尺寸。
- 完成模块后运行 `npm run typecheck:client` 和 `npm run lint`；阶段完成后再运行测试与构建。
