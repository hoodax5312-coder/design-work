# 版本管理

项目使用语义化版本（SemVer）和 Git 标签管理可回滚版本。

版本格式为 `主版本.次版本.修订版本`：

- 修订版本（Patch）：小型修复和不改变既有交互的 UI 调整，例如 `1.1.1` → `1.1.2`。
- 次版本（Minor）：新增向后兼容的模块、功能或重要交互，例如 `1.1.2` → `1.2.0`。
- 主版本（Major）：不兼容的产品结构、数据结构或工作流升级，例如 `1.2.0` → `2.0.0`。

每个正式版本必须同时具备：

1. `package.json` 与 `package-lock.json` 中一致的版本号。
2. 包含该版本完整代码的 Git 提交。
3. 指向该提交的带注释标签，格式为 `vX.Y.Z`。
4. 已推送到 GitHub 的分支与标签。
5. GitHub Release 及对应版本说明。

回滚时优先从 GitHub Release 或 Git 标签创建恢复分支，不直接覆盖当前开发分支。例如：

```bash
git switch -c restore/v1.1.1 v1.1.1
```

当前版本基线：`v1.1.1`。后续收到“发布新版本”命令时，根据改动范围自动选择 Patch、Minor 或 Major；如果用户指定版本号，则以指定版本号为准。
